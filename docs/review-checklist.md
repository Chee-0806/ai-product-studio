# 评审清单

评审分两类：**一致性评审**（PRD 与原型是否说同一件事）和**产品评审**（这件事是否值得做、是否想清楚了）。先跑 `npm run check`，机器能查的不要占用人。

## 1. PRD

- [ ] 问题有证据，不是「我觉得」；证据链接到 `discovery/`
- [ ] 目标用户与核心场景具体到能判断取舍
- [ ] 本期范围与「明确不做」都写清楚
- [ ] 每条需求有稳定 ID、优先级、用户故事、行为、验收
- [ ] 验收标准可判断真假，不是「体验流畅」这类形容词
- [ ] 状态与实际进度一致：没做的保持 `draft`，不做的标 `dropped` 并写原因
- [ ] 边界态（空/加载/错误/权限/超长）有定义
- [ ] 指标有定义、有目标值
- [ ] 开放问题有负责人，不藏在正文里
- [ ] 变更记录与版本号对应
- [ ] 重大取舍有 ADR，PRD 只链接不复述

## 2. 原型

- [ ] 每条 `prototyped` 需求都能在页面上找到对应实现
- [ ] 主流程从首页到分享能完整点通
- [ ] 每个页面有 `screen:id` / `screen:title` / `screen:flow`
- [ ] `data-req` 标在正确的元素上，不是整页
- [ ] 页面没有 PRD 未定义的功能、入口、设置项
- [ ] PRD 中「」引用的文案逐字一致
- [ ] 示例数据自洽（日期、人数、金额、状态）
- [ ] 空状态、错误态、权限态有可演示呈现
- [ ] 没有死链、空按钮、`href="#"`、lorem ipsum
- [ ] 360px 宽度下不横向滚动，内容不被裁切
- [ ] 工作台缩略图正常，分组合理

## 3. 交叉检查

- [ ] `npm run check` 通过（无错误、无警告）
- [ ] `STATE.md` 的 `spec_version` 与 PRD 一致
- [ ] 本轮改动涉及的需求 ID、页面已在 `STATE.md` 记录
- [ ] 变更记录列出了受影响需求
- [ ] 新决策已写 ADR，旧决策已标 superseded
- [ ] 没有第二份需求清单、进度表或手工映射表

## 4. 无法自动验证的项

以下必须人工判断，评审结论里要明确写「已验证 / 未验证 / 有风险」：

- 验收标准是否覆盖真实业务边界；
- 交互是否符合用户预期与业务规则；
- 文案是否准确、无歧义、符合品牌语气；
- 原型中的模拟逻辑是否会被误认为真实能力；
- 指标是否可采集、口径是否唯一。

## 5. 输出格式

```text
评审对象：PRD v0.2.0 / 3 个页面
机器校验：npm run check 通过

必改（阻塞）：
- REQ-003 验收要求「待确认」，原型第 3 条待办用了「截止时间待确认」，文案需统一
- 录音页缺少「网络中断」状态

建议（不阻塞）：
- 首页最近纪要只展示 3 条，可在 PRD 写明上限

PRD 与原型不一致：
- 无

无法验证：
- 分享链接 7 天有效（原型未实现鉴权）
```

结论只有三种：**通过 / 有条件通过 / 不通过**。有条件通过必须列出条件和复查人。
