# ADR-0003 工作台是快照与账本，不是入口

- 日期：2026-11-12
- 状态：已采纳
- 依据：AIP-7（工作台定位）、AIP-8（承诺账本）、AIP-9（变更分级）

## 背景

原来的说法是「工作台是给用户看的唯一入口」。这个说法有个前提：人只在工作台里看东西、提意见。

前提变了。Claude Code、Codex、WorkBuddy 这类 harness 打开工作台页面时，人已经能在页面上直接评论；再自建一套可写界面，等于把交互入口重做一遍，钱花在重复的地方。

那么工作台还剩什么不能替代的能力？只有一件：**留痕**。对话会丢，页面不会。它记录的是「谁答应改什么、有没有做到、哪一版被谁认过」。

## 决定

工作台定位改为**快照 + 承诺账本**：

1. 顶部一行身份：依据哪一版 PRD、检查是否通过、什么时候生成的、多少需求与页面。评审时看这一行就知道这份快照能不能用。
2. 「本轮变更」按承诺类、结构类、重写类三档逐条列出，不靠 AI 自述。
3. 「等你处理」合并未确认的承诺类改动、要人拍板的事、挂了几轮的开放问题，以及承诺账本。
4. 需求进度与原型页面降为参考，可折叠。
5. 工作台允许落后于工作区，但要显示生成时间并提示；交付与评审路径仍强制最新。

## 取舍

- 放宽「必须最新」的风险是评审拿到旧快照。兜底是身份行写明版本与生成时间，交付路径用 `npm run check:deliver` 强制最新。
- 主次翻转会改变老用户的阅读习惯。保留折叠区，不删内容。
- 账本从既有事实推导（REQ 状态、开放问题、ADR、`STATE.next_action`），不新增账本文件。多一份文件就是第二份真相。

## 被否决的方案与原因

- **自建可写工作台（页面内评论、编辑控件）**：harness 已经提供评论入口，重复投资；而且会引入第二套事实源。
- **把工作台继续当成「唯一入口」**：这个说法建立在不成立的前提上，留着会让后面的设计一直往错的方向走。
- **独立的承诺清单文件**：账本必须是推导物，否则需求和账本会各说各话。
- **工作台深色模式**：优先级下调。工作台是快照与账本，不做个性化。
