# 0002 原型采用无构建静态 HTML

- 日期：2026-11-11
- 状态：accepted
- 关联需求：全部

## 背景

原型工位需要同时满足：

- 产品经理和 AI 都能直接改；
- 评审时双击就能打开，不依赖开发环境；
- 文件可 diff、可回溯，能看出「哪次改动影响了哪个页面」；
- 不把时间花在脚手架、依赖升级和构建错误上。

## 决策

`prototype/screens/*.html` 使用原生 HTML/CSS/JS：

- 共享样式放 `prototype/assets/`，通过相对路径引用；
- 不引入 npm 依赖、CDN、框架与构建步骤；
- 交互只做「能演示流程」的程度，真实逻辑不在这里实现；
- 页面之间用相对链接串联，主流程必须能点通。

## 备选方案

- **Figma / 设计工具**：视觉强，但 agent 难以直接编辑，PRD 追溯靠人工，diff 不可读。
- **React + Vite**：交互能力强，但引入依赖与构建，评审需要起服务；对「讨论界面」是过度工程。
- **截图 / 图片**：无法交互、无法 diff，改一个字要重画。

## 代价与影响

- 复杂交互（拖拽、实时协同）不适合用静态原型验证，需要更早进入技术验证。
- 没有组件复用机制，重复结构靠共享 CSS 与约定控制，页面多了会需要模板脚本。
- 样式只在现代浏览器验证；不作为生产代码交付。
