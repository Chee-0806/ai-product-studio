# 产品设计工位（启动技能）

工位本体是一个普通文件夹：`product/PRD.md` 是需求唯一事实源，`prototype/` 是可点原型，`工作台.html` 是人看的唯一入口，`AGENTS.md` 是 AI 的工作契约。本技能负责把它从模板铺出来，并保证之后每轮工作都落在工位里，而不是只留在对话里。

## 什么时候用

- 用户想开始一个新产品，手上还没有工位（空文件夹或桌面新建的文件夹）。
- 已有工位要升级到新版本的规则、脚本和技能。
- 工位打不开、检查失败、工作台不刷新，需要判断是环境问题还是内容问题。

## 建工位

1. 只问一句产品名；不要先问范围、用户、功能。
2. 目标位置：当前文件夹为空就用它；不为空就在里面建一个以产品名命名的子文件夹。
3. 运行（`<技能目录>` 是本技能所在目录的绝对路径）：

   ```bash
   node "<技能目录>/template/scripts/new.mjs" "<目标目录>" --name "<产品名>"
   ```

4. 进入目标目录，运行 `node scripts/sync.mjs`，确认工作台已生成。
5. 直接打开工作台：macOS `open 工作台.html`，Windows `start "" 工作台.html`，Linux `xdg-open 工作台.html`。
6. 用产品语言告诉用户：以后直接把想法说给 AI，不需要命令、git 或文件管理；每次改完你会把工作台刷新好并打开。

没有装本技能时，按仓库根目录的 `BOOTSTRAP.md` 走同样的流程。

## 升级工位

1. 先确认目标确实是工位：同时存在 `AGENTS.md` 和 `product/PRD.md`。
2. 运行：

   ```bash
   node "<技能目录>/template/scripts/upgrade.mjs" "<工位目录>"
   ```

3. 升级只替换规则、脚本、技能、文档和共享样式；`product/`、`prototype/`、`STATE.md`、`工作台.html` 不动。
4. 进入工位运行 `npm run sync && npm run check`；失败就修到通过，不要把红色状态留给用户。
5. 打开工作台给用户看，并告诉她这次升级了什么、产品内容没有变。

## 诊断

- 先运行 `node -v`。低于 18 或没有 Node：先说明「需要装一个运行环境，大概两分钟」，得到同意再装。有 Homebrew 用 `brew install node`，没有就下载官方安装包，要管理员密码时请用户输入。装完复验。
- 装不上（没网络、没权限）：如实说清缺什么，不要静默降级成 AI 自查，也不要让她执行命令。
- 再查工位骨架：`AGENTS.md`、`scripts/sync.mjs`、`skills/`、`STATE.md` 是否齐全。
- 运行 `npm run check`，把失败项翻译成产品语言，能自己修的直接修。
- 工作台打不开或过期：运行 `npm run sync` 后让用户重新双击。

## 不要做

- 不要在用户确认产品名前建站，也不要替用户决定放在哪个目录。
- 不要把模板铺进一个已经有内容的项目；那需要先和用户确认目标子目录。
- 不要要求用户运行 npm、node、git 或任何命令。
- 不要未经同意安装系统软件。
- 不要在没有 Node 时假装检查通过，也不要手工伪造 `工作台.html`。
- 不要把工位做成聊天记录：对话里产生的决定、需求和进度必须写进文件。

## 版本

同目录 `VERSION` 是本技能内置的模板版本；升级工位时以它为准，不要从网络另取模板。
